# ADR-0004: 待办列表窗口层级与双快捷键

- Status: Accepted
- Date: 2026-10-29

## Context

用户反馈贴桌面最底层不便查看；要求「显示待办」与「快速记录」均支持可配置全局快捷键；快捷键唤起待办列表时应浮于当前前台窗口之上。此前 ADR-0003 / OBJECTIVE 将列表定为桌面层。

## Decision

- 待办列表改为**普通顶层窗口**：启动时不再 `SetParent` 到桌面宿主；位置仍持久化，拖动使用标准窗口坐标。
- 默认快捷键：**快速记录** `Ctrl+Alt+N`，**显示待办** `Ctrl+Alt+L`；均在设置页可改，保存时校验非空、长度、两者不得相同，并重新注册全局快捷键。
- **显示待办**（全局快捷键、托盘菜单「显示待办」、托盘左键）唤起列表时：`show` + `set_focus`，并 `always_on_top(true)`；**收起到托盘**时取消置顶。快速记录窗仍为普通前台窗，不抢列表的置顶语义。
- 保留 `desktop` 模块与 `LITTLETODO_QA_UNPIN` 供探针/旧路径；新默认路径不再调用 `attach_panel`。若检测到列表仍挂在桌面父窗口下，启动时先 `detach` 再定位。

## Consequences

- C3 验收语义变更：不再要求 Win+D 后列表仍可见；改为快捷键/托盘可恢复列表且快捷键唤起时置顶。
- macOS M5 需实现等价的列表置顶与双快捷键，不再依赖 Windows 桌面层。
- OBJECTIVE 中「贴桌面列表」表述需与用户 2026-10-29 重基线对齐。
